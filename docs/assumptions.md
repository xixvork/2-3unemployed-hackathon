# Assumptions

## Why this file exists

У тестовому завданні є вимога фіксувати обґрунтовані припущення, якщо даних бракує.
Нижче перелік припущень, які команда використовувала під час реалізації.

## Product and domain assumptions

- Працюємо лише в межах `New York State`, як зазначено в умові.
- `subtotal` означає ціну без податку.
- `timestamp` у вхідних даних приходить у форматі ISO-8601.
- Для MVP достатньо обробляти замовлення без складних статусів життєвого циклу.

## API assumptions

- `POST /orders/import` приймає файл у `multipart/form-data`, поле `file`.
- Для `GET /orders` потрібна пагінація та базові фільтри.
- Грошові значення в API краще передавати як рядки, щоб уникати проблем із floating-point.
- Поле `jurisdictions` є бонусним і може бути відсутнім на ранньому етапі реалізації.

## Data assumptions

- Tax-ставки беруться з локального датасету, без runtime-запитів до сторонніх API.
- Геокодування/мапінг координат до юрисдикції може мати похибки на межах районів.
- Для імпорту CSV очікується стабільний набір колонок (`latitude`, `longitude`, `subtotal`, `timestamp`).

## Delivery assumptions

- Для хакатону пріоритет: коректний бізнес-потік і прозорий контракт API, а не production-hardening.
- Документація в `docs/` є робочим джерелом правди до фінального узгодження в `README`.
